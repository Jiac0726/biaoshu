- [x] 招标原文读取：TXT/MD，PDF/DOCX 可选依赖
- [x] 证据字段、评分响应映射、事实状态机械检查

- [x] 机械审计报告与基础 DOCX 草稿导出
- [x] 主 Skill、阶段性写作规则、单元测试与 CI
- [x] PDF 页号、DOCX 正文段落与表格行顺序定位及回归测试
- [ ] 复杂 PDF/DOCX：合并单元格、页内表格、文本框和页码的真实案例回归
- [ ] 端到端样例与文档示例验证

## 阶段 B：智能分析与目录编排

- [ ] 招标结构化 JSON Schema + 校验报告分级
- [ ] 评分项/技术评分要求区分的真实案例基准
- [ ] 否决性与实质性条款独立清单
- [ ] 支持父子目录树、一级目录确认与已确认目录锁定
- [ ] 原方案内容比对与保留策略

## 阶段 C：Agent 写作与质量闭环

- [ ] 模型适配层（本地与 API；由用户明确选用）
- [ ] 按需引用知识库/原文片段，标记来源
- [ ] 多章节并发执行、检查点与失败恢复
- [ ] 语义一致性台账、全局事实回写、定点修复
- [ ] 长度调整与信息保全检查

## 阶段 D：投标级输出

- [ ] Word 模板映射：标题编号、样式、页眉页脚、分页
- [ ] 表格、图注、目录域和图片素材
- [ ] 暗标/电子标格式独立配置
- [ ] 从证据到最终正文的可追溯审核表
- [ ] 与其他 Agent 宿主的 Skill 适配测试

## 安全与工程原则

- 真实客户投标材料默认本地；无明确授权不传云、不写到公共仓库。
- 自动任务优先在单独分支提交 PR，人工审查后合并。
- 只迁移通用业务方法，不复制 OpenBidKit 源码；若后续复用第三方实现，须先核实许可条件。
- 每项能力都要有可运行测试和明确的“已实现/未实现”边界。
