# 全局事实与承诺口径

以 facts.json 为跨章节唯一事实基线。要覆盖至少下列需要核验的主题：项目名称、实施地点、服务范围、工期或交付期限、质量目标、响应时限、人员、设备、成果交付、保密及运维（以实际项目适用范围为准）。

## 三种状态

- verified：已由来源证明的具体值；必填 evidence.file / location / quote。
- pending：材料未明确但需要用户或企业内部确定，禁止擅自写成已承诺。
- not_specified：招标原文未提及，该事实的 value 留空。

示意：

```json
{
  "facts": [
    {
      "key": "project_duration",
      "value": "",
      "status": "pending"
    }
  ]
}
```

## 冲突处理

若招标文件、澄清、用户授权信息、旧方案或知识库之间有冲突，先列出冲突证据及适用版本；不得因旧方案写得更具体就默认用旧值覆盖新招标约束。获得合法授权后更新事实基线并标记受影响章节重查。

不要将项目背景、评分扣分规则和写作建议伪装为项目实际情况；禁止虚构企业业绩、投入资源和证明文件。
