# 全文质量审查（机械 + 语义 + 人工）

## 机械检查

使用 python -m biaoshu check 和 audit 检查：
- 需求 ID、章节 ID、事实 key 唯一；
- 招标需求是否提供原文证据（文件、位置、引文）；
- 需求—小节映射是否完整和双向一致；
- 已核实事实是否有来源；未提及事实是否被错误填值；
- 正文是否存在、是否仍包含 TODO、是否明显低于目标字数。

上述检查**不验证真实原文是否准确**，也不能发现大部分跨章节语义矛盾。

## Agent 语义审核

建立“评分项 → 具体原文 → 响应章节 → 响应段落 → 验收标准”的逐项核对表，确认没有漏项、错位、泛泛回应、同义重复和互相冲突。

重点检测：
- 不同章节中项目范围、地点、周期和交付期限是否矛盾；
- 组织人员、工作量、设备数量、执行频率、技术指标是否互相冲突；
- 计划和保证措施是否可执行、可检查；
- 招标强制格式、匿名暗标、盖章、签名、附件、商务或资格要求是否需要另行核查；
- 是否有无法证实的企业资质、业绩、经验、第三方数据或过度承诺；
- 是否误将评分解释文字作为独立评分项，或漏掉实际必须展开的方案内容。

每个问题应写明：严重程度、需求 ID、章节 ID、问题原文、依据、建议改法、是否需用户确认。对难以确认的事实不要用 AI 猜测填空。

## 审查出口

程序 pass + Agent 逐项审核通过 + 用户/投标负责人确认，才可以作为正式终稿的候选。当前 export 工具仅输出基础 Word 草稿，仍需按招标具体格式核对。


## 可定位的跨章节数值机械审查

命令 consistency-audit <project_dir> [--output report.json] 以只读方式扫描 sections/<ID>.md。仅对工期、服务期限、质保期、响应时限里明确写出的单一值和单位比对，并与 facts.json 同类别 verified 的简单单值基线交叉验证。对章内/跨章矛盾生成 error，包含章节和实际行号；pending 事实产生 warning。相同含义的 天/日、个月/月 只作表述归一，不擅自把月份换算成天数，也不推断上下限、条件和否定句。普通 check 报告警告，strict audit 与正式 export 因明确 error 失败关闭。

此程序的通过并非投标专业一致性或招标文件遵从性证明。人工/Agent 必须继续检查质量标准、人员岗位、设备清单、企业资质、项目范围、原文评分覆盖、服务等级、法规适用版本以及正文与原文之间的语义偏差。不要让自动修复覆盖已审核章节。
