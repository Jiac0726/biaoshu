# 评分驱动的技术标目录规划

## 核心约束

1. 先识别独立技术标还是完整投标文件；如果技术标单独成册，不要强加商务、报价或资格章节。
2. 技术评分大项优先一一对应同层级的目录节点，标题尽量使用原评分项术语，保持原有先后次序。
3. 评分细项用于展开下级逻辑，不要求每一分值都单独成为一级目录；跨章节共享内容可以允许多对多映射，但要清晰注明。
4. 不产生无内容的一级包裹层，不生成只有一个子节点的冗余层级，不为达到字数盲目拓展目录。
5. 有原技术方案时：保留实质信息，在不违反招标要求的前提下作为下级内容来源；不要简单复制不适用的原项目事实。
6. 用户确认过的一级目录，不经批准不得删改、重新排序、合并或新增。

## 项目内数据结构

outline.json 用扁平叶子模型管理可独立撰写章节，目录显示层级可以在后续版本单独扩展。

```json
{
  "sections": [
    {
      "id": "S1",
      "title": "项目组织与实施",
      "requirement_ids": ["R1"],
      "weight": 1.0,
      "target_words": 0
    }
  ]
}
```

requirements.json 的相应项必须设置 response_sections=["S1"]。对应关系是双向一致性规则。当前 Python 工具只判断映射完整和 ID 合法，不会判断 R1 与 S1 的专业含义是否真的一致；Agent 需逐项对照原文复核。
