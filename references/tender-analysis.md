# 招标文件分析：抽取与证据登记

## 分析顺序

1. 确定招标文件是否完整：公告、招标须知、技术要求、评审办法、合同条款、澄清和附件。
2. 优先定位“技术评分”“评审因素”“技术方案”“技术要求”“实质性条款”“响应偏离”等目录或关键词，但不得因此忽略其他章节。
3. 对每项评分因素区分：**需要展开书面方案的技术评分项**、**仅用于评分计算的约束/扣分规则**、**商务/价格/资格因素**。不要把“评分规则”自动提升为技术方案标题。
4. 为每个需要响应的评分项记录原文引述，分别保留正式标题、分值、细则、文件与位置。
5. 逐项形成需要写作的响应范围；原文提及且必须响应的内容不因缺分值就删除。
6. 单独整理废标/否决性风险清单，不能通过增加技术正文代替对资格、签章、封装和商务材料的人工检查。

## 输出约定

requirements.json：

```json
{
  "requirements": [
    {
      "id": "R1",
      "title": "评分大项标题（原文）",
      "description": "必须响应的技术内容",
      "score": 10,
      "evidence": {
        "file": "招标文件.pdf",
        "location": "第 21 页/技术评分表",
        "quote": "实际招标原文摘录"
      },
      "response_sections": ["S1"]
    }
  ]
}
```

注意：以上是结构示意，不是实际招标内容，不得复制示例标题、分值或引文到真实项目。若原文页码不可靠，保留可复查章节/表格位置并注明不足。需求条目不可只存模型总结而缺少原文证据。
